# Archcodex 0.8.0 — Restore opened terminals

Development release for Linux host testing. Adds workspace restoration requested
in [#3](https://github.com/emsi/Archcodex/issues/3), with the in-TUI navigation
limitations described below.

## Changes

- Remember opened terminal views, the selected terminal and recent-terminal order
  across application restarts. Restoration is enabled by default in
  **Settings → Application → Restore opened terminals on startup**.
- Show remembered views immediately in **Opened**. Ready sources restore
  independently; offline sources retain their placeholders. Background restores
  preserve focus and ordering. Previously exited or failed clients require an
  explicit reconnect.
- Verify exact conversation IDs and container execution context before opening.
  Shared myCodex history cannot authorize execution in another container.
- Add nonmodal workspace details and retain failed views with actionable messages.
  Store workspace intent separately from the session cache and preserve unreadable
  or unsupported records.

## Known limitations and upgrade

Restoration remembers the conversation **opened by Archcodex**. Switching inside
Codex with `/resume`, `/fork`, `/new` or agent navigation can leave that saved target
unchanged, so restart can reopen the original conversation. `/rename` updates still
work. A New terminal without a confirmed conversation ID remains a disconnected
placeholder after restart; open its saved conversation from Projects to remember
it reliably. GUI Fork uses the confirmed ID returned by the server.

Terminal output is retained during the current run but is not saved across restarts.
Some conversations archived while Archcodex was offline may be rejected by the TUI;
its error is retained without an automatic retry loop.

**The metadata database upgrades to schema 2.** Before upgrading, quit Archcodex
and back up its application data directory, normally
`~/.var/app/io.github.emsi.Archcodex/data/archcodex/`. Returning to 0.7.1 or earlier
requires that pre-upgrade backup or a separate data directory.

No Codex patch, protocol-observation proxy or additional transport processes are
introduced. KDE 6.11, Konsole 26.04.3 and Flatpak permissions are unchanged.

## Install or update

Download `Archcodex-0.8.0-x86_64.flatpak` and `SHA256SUMS` from this release into
the same directory. Quit Archcodex, then run in your **local host terminal**,
outside myCodex or another container:

```sh
sha256sum -c SHA256SUMS
flatpak install --user --or-update ./Archcodex-0.8.0-x86_64.flatpak
flatpak run io.github.emsi.Archcodex
```

The bundle targets **x86_64 Linux with X11/XWayland**. A compatible local Codex CLI
and independently running app-server are required. myCodex terminals require local
Codex 0.166.0 or newer and a running systemd user manager; Docker/Python 3 and SSH
requirements are unchanged.

## Verification and source

This release publishes the existing locally built Flatpak unchanged. Its nine
recorded test suites pass, including 22 X11 window cases, 17 terminal cases and
28 model cases. Isolated installation and the packaged window/Konsole smoke test
passed. Full Flatpak sandbox execution and real desktop/remote restore acceptance
remain unverified in the build container because it prohibits user namespaces.
